## 2. База: `navchannia.db`

Файл `/var/lib/beregynia/navchannia.db` (поруч із `beregynia.db`), як
задумано в `kabinet-navchannia.md` §4. Шлях — змінна `NAVCH_DB_PATH` у
`.env`, за замовчуванням поруч із `DB_PATH`. Створення й міграції — так
само, як `init_db()` / `_migrate()` для основної бази. WAL, як і основна.

```sql
-- діти програми 5–8 (у children їх немає: анкети садочка не існує)
CREATE TABLE IF NOT EXISTS dity (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  imia        TEXT NOT NULL,           -- ім'я і прізвище, як скаже мама
  vik         INTEGER,                 -- 5, 6, 7, 8
  login       TEXT UNIQUE NOT NULL,
  pass_hash   TEXT NOT NULL,
  bukvar      TEXT NOT NULL DEFAULT 'bolshakova',  -- bolshakova | vashulenko
  created_at  TEXT NOT NULL,
  created_by  TEXT NOT NULL,           -- логін адміністратора
  last_login  TEXT
);

-- активовані пристрої
CREATE TABLE IF NOT EXISTS prystroi (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  nazva       TEXT NOT NULL,           -- «Планшет ГО», «Телефон мами Олі»
  token_hash  TEXT UNIQUE NOT NULL,    -- sha256 токена; сам токен лише в куці
  created_at  TEXT NOT NULL,
  created_by  TEXT NOT NULL,
  last_seen   TEXT,
  revoked_at  TEXT
);

-- одноразові коди активації
CREATE TABLE IF NOT EXISTS kody (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  code_hash   TEXT UNIQUE NOT NULL,
  nazva       TEXT NOT NULL,           -- стане назвою пристрою
  created_at  TEXT NOT NULL,
  created_by  TEXT NOT NULL,
  expires_at  TEXT NOT NULL,           -- +24 год
  used_at     TEXT,
  prystrii_id INTEGER
);

-- заняття: одне на урок, стартову або повторну перевірку
CREATE TABLE IF NOT EXISTS zaniattia (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  dytyna_id   INTEGER NOT NULL,

  pochatok    TEXT NOT NULL,           -- час із клієнта, перевірений сервером

-- підсумок заняття по навичках: лише лічильники

-- «Я підготувався» — тепер на сервері й окремо для кожного педагога
```

Маршрути в тому самому Flask-застосунку (`server/app.py` або новий модуль
`server/uroky.py`, підключений до `app`). Усе під префіксом `/uroky`:

**Застава** — доповнити `gate()`, а не перевіряти в кожному маршруті:

* усе під `/uroky`, крім `/uroky/aktyvatsiia`, `/uroky/api/aktyvatsiia`,
  manifest, sw.js та іконок, вимагає **дійсну куку пристрою** (§4);
  без неї → редірект на `/uroky/aktyvatsiia`;
* усе під `/uroky`, крім активації та входу, вимагає сесію
  `kind in ('mama', 'staff')`; без неї → `/uroky/vkhid`;
* мама (`kind='mama'`) отримує доступ лише до своєї `dytyna_id`:
  сервер підставляє її сам, параметр від клієнта ігнорує;
* персонал (`kind='staff'`) мусить спершу обрати дитину
  (`session['dytyna']`), інакше → `/uroky/dity`.

**Сесія мами:** `kind='mama'`, `dytyna`, `name`. Живе 30 днів (мамі на
телефоні незручно щодня вводити пароль; пристрій і так активований).
**Сесія персоналу на lab:** як в адмінці, 8 годин. Кука сесії
host-only — вхід на lab і на основному домені окремі.

Ліміт спроб — як у `pupil_login` (за логіном, 10 за 15 хв) і в `login`

## 4. Активація пристроїв

Мета: уроки відкриваються лише на пристроях, які схвалив адміністратор.

**Як це виглядає:**
1. Адміністратор в адмінці (§10) натискає «Новий код», пише назву
   («Телефон мами Олі»). Сервер показує **один раз** код із 8 цифр,
   дійсний 24 години, одноразовий.
2. На пристрої відкривають `lab…/uroky` → їх перекидає на
   `/uroky/aktyvatsiia` → вводять код.
3. Сервер створює запис у `prystroi`, генерує токен
   `secrets.token_urlsafe(32)`, у базу пише лише `sha256` токена,
   а токен ставить у куку `beregynia_dev`: `HttpOnly`, `Secure`,
   `SameSite=Strict`, `Path=/uroky`, строк 400 днів.
4. Кожен запит під `/uroky` перевіряє куку: хеш є в `prystroi`,
   `revoked_at IS NULL`. `last_seen` оновлювати не частіше ніж раз на
   годину (щоб не писати в базу на кожен запит).

**Відкликання:** в адмінці кнопка «Відкликати» → `revoked_at`. Наступний
запит з цього пристрою → на сторінку активації.

**Захист коду від перебору:** не більше 5 невдалих спроб з однієї IP за
15 хвилин (таблиця `login_attempts`, як для входу персоналу). Код
порівнювати через хеш, у базі сам код не зберігається.

**Підводні камені — обов'язково написати на сторінці активації
простими словами:**
* Очищення даних браузера знімає активацію — потрібен новий код.
* **iPhone:** застосунок, встановлений на головний екран, має окремі
  куки від Safari. Тому порядок такий: спершу «На екран „Додому“», потім
  відкрити значок і вже там ввести код.
* Різні браузери на одному пристрої — різні активації.

## 6. Прогрес: сервер — джерело правди

**Правило засвоєння рахує сервер**, клієнт лише показує. Функція
`stan(dytyna_id)` у Python повторює чинне правило з `uroky.html`
(рядок з `total >= 3 && days >= 2`):

* **засвоєно** — щонайменше 3 правильні з першої спроби, у щонайменше
  2 різні дні (дні — за київським часом, `Europe/Kyiv`);
* **застряг** — останні 3 заняття з цією навичкою без жодної правильної
  з першої спроби;
* **вчиться** — є заняття, але ні те, ні інше;
* **не почато** — занять немає.

Перевірки (`vyd in ('start','povtor')`) у «засвоєно» **не** зараховуються —
як і зараз. Рекомендований урок (чергування ліній Г → М → Ф → А з
`uroky-12.md` §D) теж рахує сервер і віддає в `/uroky/api/stan`.

**Тільки заняття педагога (§0 п. 7).** `stan()` бере до уваги лише
`zaniattia` з `khto='vchytel'`. Заняття мами (`khto='mama'`) — окремий
лічильник «повторювали вдома» по уроку й навичці, на статуси не впливає.

**Що доступно мамі:** лише уроки, у яких є хоча б одне заняття педагога
з цією дитиною. Рекомендація для мами — серед них: спершу уроки з
навичками «вчиться», найсвіжіші за датою заняття педагога; «засвоєно» —
теж можна, для закріплення. Решта уроків у списку мами не показується
(не сірим, а взагалі), щоб не було спокуси «піти вперед». Стартова й
повторна перевірка мамі недоступні. Сервер перевіряє це сам: `POST`
заняття мами з уроком, якого педагог не проводив, → 403.

Якщо педагог ще не провів жодного уроку — мама бачить коротке
пояснення: «Уроки з'являться тут після першого заняття з педагогом».

**Що відправляє клієнт після заняття** (`POST /uroky/api/zaniattia`, JSON):

```json
{"klient_id": "uuid4", "vyd": "urok", "urok": "g01",
 "pochatok": "2026-11-02T10:14:00+02:00",
 "navychky": {"Г01": {"pershi": 6, "usogo": 8}}}
```

Сервер перевіряє: урок існує, навички належать цьому уроку, `pershi <=
usogo <= 20`, `pochatok` не в майбутньому і не старіший за 14 днів.
`kinets`, `khto`, `staff_login`, `prystrii_id`, `dytyna_id` бере **з
сесії та куки**, не з тіла запиту. Відповідь — новий `stan` і
рекомендація, щоб клієнт одразу оновив список уроків.

**Прибрати з `uroky.html`:** зберігання прогресу й підготовки в
`localStorage`, підрахунок статусів на клієнті, перемикач ролі.
Лишити: `try/catch` навколо `localStorage` для черги (§7).

## 7. Черга без мережі

Світло й інтернет у Покрові зникають. Заняття не повинно пропасти.

* Підсумок заняття спершу кладеться в чергу `localStorage`
  (`beregynia-cherga`), потім відправляється.
* Успіх (`200`) або «вже прийнято» (`409` на той самий `klient_id`) →
  прибрати з черги. Сервер на повторний `klient_id` відповідає 409 і
  нічого не дублює.
* Помилка мережі → лишити, повторити при `online`, при відкритті
  сторінки й кожні 60 с, поки сторінка відкрита.
* Сесія закінчилась (`401`) → лишити в черзі, після входу відправити.
  Сервер прийме, лише якщо дитина з черги та сама, що в сесії (мама)
  або існує (персонал); інакше відповідь 403, і запис прибирається з
  черги з повідомленням дорослому.
* Поки в черзі щось є, у куті екрана для дорослого — маленьке
  «Не відправлено: N» (дитині не заважає).
* Сам урок без мережі не відкриється (оболонку й стан дає сервер) —
  це прийнятно; не відкриється тихо, а з простим поясненням.

## 8. Сторінка стану `/uroky/stan`

Для мами — головне «дзеркало», для педагога — та сама сторінка по
обраній дитині. Телефон насамперед.

* Угорі — **календар занять** за останні 8 тижнів: клітинка на день,
  заповнена, якщо було заняття (регулярність важливіша за бал —
  `kabinet-navchannia.md` §1).
* Далі чотири лінії (Грамота · Математика · Геометрія · Англійська),
  у кожній — навички з людськими назвами (зі `skills.csv`, колонка
  `skill`) і статусом: не почато / вчиться / засвоєно / застряг.
* Для «застряг» — одне речення, що робити («Пограйте в …» з колонки
  «робимо разом» методичної таблиці).
* Календар розрізняє заняття з педагогом і домашні повторення (дві
  різні позначки в клітинці). Біля навички — «повторювали вдома: N разів»,
  щоб педагог бачив, що робиться вдома.
* Жодних балів, відсотків і порівнянь з іншими дітьми.

## 10. Адмінка (основний домен, `/admin`)

Нова сторінка `/admin/mudryk` (у `gate()` вона вже під заставою персоналу).
Дії, що змінюють дані, — **лише роль `admin`**; `teacher` бачить список,
нічого не змінює.

* **Діти:** таблиця (ім'я, вік, логін, буквар, останнє заняття, засвоєно
  навичок). «Додати дитину» → ім'я, вік, буквар → логін і пароль
  показуються **один раз** з кнопкою «Друкувати картку для мами»
  (логін, пароль, адреса, коротко як увійти). «Новий пароль».
  «Видалити дитину» з підтвердженням → разом із заняттями (§2).
* **Пристрої:** таблиця (назва, активовано, ким, востаннє бачили,
  статус). «Відкликати».
* **Коди:** «Новий код» → назва → код показується один раз; список
  невикористаних кодів зі строком дії, «Скасувати».
* Посилання в картці стану дитини на `/uroky/stan` не робимо (різні
  домени — різні сесії); у таблиці дітей достатньо коротких цифр.

## 10б. Перевірка перед здачею (прохід 4)

* Розширити `lab/perevirka-uroky.js`: піднімає Flask локально з
  тимчасовими базами (`DEV=1`), створює адміна, дитину, код.
* Без куки пристрою будь-яка сторінка `/uroky*` (крім активації) →
  активація. З відкликаним пристроєм — те саме.
* Неправильний код 5 разів → блокування на 15 хв. Код другий раз не
  спрацьовує. Прострочений — не спрацьовує.
* Мама бачить лише свою дитину: підміна `dytyna_id` у запиті нічого не
  дає; `/uroky/dity` для мами → 403 або редірект.
* Педагог: вибір дитини → урок → підсумок у базі з `khto='vchytel'`.
* Мама: до першого заняття педагога список уроків порожній з поясненням;
  після — лише пройдені з педагогом уроки. Прямий `POST` заняття мами з
  іншим уроком → 403. Скільки б мама не повторювала (навіть 3 правильні
  у 2 дні), статус навички не змінюється; лічильник «вдома» росте.
  Перевірки для мами недоступні.
* Правило засвоєння на сервері: 3 правильні в один день → «вчиться»;
  у два дні → «засвоєно»; 3 заняття з нулем → «застряг». Перевірки не
  зараховуються.
* Черга: обірвати мережу посеред уроку → підсумок у черзі → мережа є →
  відправлено один раз (повтор → 409, без дубля).
* Видалення дитини видаляє її заняття; копія бази містить обидві бази.
* Старі перевірки уроків (усі уроки до зорепаду, правило §0 голосу,
  англійська без перекладу) проходять на телефоні, планшеті, ПК.
* Консоль чиста; жодних запитів за межі домену.

## 11. Прохід 5: зміст на сервері

Робиться після проходу 4 — тією ж сесією, але **лише якщо всі перевірки
проходу 4 (§10б) зелені** і прохід 4 уже закомічено й запушено окремим
комітом. Якщо перевірки проходу 4 не проходять — прохід 5 не починати,
а описати, що зламано.

* `LESSONS` виноситься з `uroky.html` у файли `server/uroky/lessons/<id>.json`
  (по одному на урок). Оболонка `uroky.html` — лише рушій.
* `GET /uroky/api/urok/<id>` віддає завдання уроку — тільки з
  активованого пристрою, тільки після входу, тільки доступний урок
  (з рекомендації чи вже відкритий для цієї дитини).
* Матеріал для вчителя (підготовка, «Я показую», «Робимо разом»,
  труднощі) — окремим `GET /uroky/api/pidhotovka/<id>`, **лише
  `kind='staff'`**. Мамі не віддається навіть за прямим запитом.
* У матеріалі для вчителя — непомітний підпис унизу:
  «ГО «Берегиня» · <логін педагога> · <дата>» (щоб видно, звідки «спливло»).
* Відповіді до завдань лишаються на клієнті (дитині потрібна миттєва
  реакція) — це свідомо: по одному уроку, а не вся програма.
* «Доступний урок» для мами — правило з §6 (лише пройдені з педагогом).
* Записані звуки (`/uroky/audio/`) — теж лише з активованого пристрою
  (уже з проходу 4).

**Перевірка проходу 5:**
* У `uroky.html` (тому, що віддає сервер) немає ні завдань, ні матеріалу
  для вчителя — лише рушій. Пошук слів із будь-якого уроку по файлу
  нічого не знаходить.
* `GET /uroky/api/urok/<id>` без куки пристрою, без входу, для
  недоступного уроку → відмова (редірект або 403).
* `GET /uroky/api/pidhotovka/<id>` у сесії мами → 403; у сесії
  персоналу → матеріал із підписом «ГО «Берегиня» · логін · дата».
* Усі перевірки проходу 4 і старі перевірки уроків (усі уроки до
  зорепаду на телефоні, планшеті, ПК; правило голосу §0; англійська
  без перекладу) — проходять.
